Level 1.1 – List Recent Connections & PIDs

Midterm – Section 1, Question 1

📋 Question:

How can you retrieve a list of recent connections and process IDs (PIDs) in PostgreSQL?

✍️ Try it yourself:

    Step 1: Identify the right tool

    PostgreSQL provides a system view called pg_stat_activity that shows information about current database connections and activities.

    Step 2: Select relevant columns

    The most important columns are: pid (process ID), usename (username), datname (database name), and state (connection state).

    Step 3: Write the query

    Use a SELECT statement to retrieve these columns from pg_stat_activity.

    Step 4: Why this works

    This query gives you a real-time snapshot of all active connections, which is essential for monitoring and troubleshooting database performance and connection issues.

    Final Answer: 
    SELECT pid, usename, datname, state
FROM pg_stat_activity;

    Level 1.2 – Cancel and Terminate Connections

    Midterm – Section 1, Question 2

    📋 Question:

    Assume that you need to terminate a specific connection to the PostgreSQL database. How can you cancel active queries on a connection with a given PID, and how can you terminate the connection itself?

    ✍️ Try it yourself:

      Step 1: Understand the difference

      pg_cancel_backend() attempts to cancel the current query gracefully, while pg_terminate_backend() forcefully terminates the entire connection.

      Step 2: Cancel a query (gentle approach)

      Use pg_cancel_backend(pid) to stop a running query without disconnecting the client. Replace 'pid' with the actual process ID.

      Step 3: Terminate a connection (forceful approach)

      Use pg_terminate_backend(pid) to immediately close the connection. This should be used when canceling doesn't work.

      Step 4: Why this is correct

      These functions give you control over individual connections. Always try canceling first (less disruptive), then terminate if necessary. Both require the PID from pg_stat_activity.

      Final Answer: 
      -- To cancel a query (gentle):
SELECT pg_cancel_backend(12345);  -- Replace 12345 with actual PID

-- To terminate a connection (forceful):
SELECT pg_terminate_backend(12345);  -- Replace 12345 with actual PID

      Level 1.3 – Kill All Connections for a Role

      Midterm – Section 1, Question 3

      📋 Question:

      How can you kill all connections belonging to a specific role in PostgreSQL?

      ✍️ Try it yourself:

        Step 1: Identify connections by role

        Query pg_stat_activity to find all PIDs where usename matches the target role name.

        Step 2: Use a subquery approach

        Combine pg_terminate_backend() with a SELECT statement that filters by username.

        Step 3: Write the complete query

        Use SELECT with pg_terminate_backend() to terminate all matching connections. The WHERE clause filters by role name and excludes your own connection.

        Step 4: Why this is correct

        This approach automatically handles multiple connections for the same role. The pid <> pg_backend_pid() condition prevents you from accidentally terminating your own connection.

        Final Answer: 
        SELECT pg_terminate_backend(pid)
FROM pg_stat_activity
WHERE usename = 'role_name'  -- Replace with actual role name
  AND pid <> pg_backend_pid();  -- Don't kill your own connection

        Level 2.1 – Create dev_user with Permissions

        Midterm – Section 2, Question 1

        📋 Question:

        Create a new user in the database named "dev_user" with a password of your choice, but ensure that the user is valid only until a specific date. Grant this user permission to read and write to a specific table named "employee_data".

        ✍️ Try it yourself:

          Step 1: Create the user with LOGIN

          Use CREATE ROLE with LOGIN option to create a user that can connect to the database.

          Step 2: Set password and expiration

          Add PASSWORD clause for authentication and VALID UNTIL to set an expiration date.

          Step 3: Grant read permissions

          Use GRANT SELECT to allow reading data from the employee_data table.

          Step 4: Grant write permissions

          Use GRANT INSERT, UPDATE to allow writing and modifying data.

          Step 5: Why this is correct

          This creates a temporary user account with limited permissions. The VALID UNTIL clause ensures the account automatically expires, enhancing security. The specific table permissions follow the principle of least privilege.

          Final Answer: 
          -- Create user with password and expiration
CREATE ROLE dev_user WITH LOGIN
PASSWORD 'secure_password123'
VALID UNTIL '2024-12-31';

-- Grant read and write permissions
GRANT SELECT, INSERT, UPDATE ON employee_data TO dev_user;

          Level 2.2 – Create dev_team Role with Inheritance

          Midterm – Section 2, Question 2

          📋 Question:

          Create a new role in the database named "dev_team" and assign the "dev_user" to this role. Grant the "dev_team" role permission to access all tables in the database, but ensure that this permission is inherited by all members of the "dev_team" role.

          ✍️ Try it yourself:

            Step 1: Create the role (not a login user)

            Use CREATE ROLE dev_team without LOGIN option. This creates a group role.

            Step 2: Grant permissions to all tables

            Use GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public to give access to all tables in the public schema.

            Step 3: Add dev_user to dev_team

            Use GRANT dev_team TO dev_user to make dev_user a member of the dev_team role.

            Step 4: Ensure inheritance is enabled

            By default, PostgreSQL roles inherit permissions. You can explicitly set this with ALTER ROLE dev_user INHERIT.

            Step 5: Why this is correct

            Group roles allow centralized permission management. When you add users to dev_team, they automatically inherit all permissions. This makes it easy to manage permissions for multiple developers.

            Final Answer: 
            -- Create the dev_team role
CREATE ROLE dev_team;

-- Grant access to all tables
GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO dev_team;

-- Add dev_user to dev_team
GRANT dev_team TO dev_user;

-- Ensure inheritance (usually default, but explicit is good)
ALTER ROLE dev_user INHERIT;

              Level 3.1 – Create Database and Table

              Midterm – Section 3, Question 1

              📋 Question:

              Create a database called "sample_db" with a single table called "sample_table". The table should have the following columns:

              • id: a serial column which automatically increments with each row added
              • name: a character varying column with a maximum length of 50 characters
              • age: a numeric column with a precision of 4 and a scale of 2
              • description: a text column

              ✍️ Try it yourself:

                Step 1: Create the database

                Use CREATE DATABASE sample_db; to create a new database.

                Step 2: Connect to the database

                Use \c sample_db in psql to connect to the new database.

                Step 3: Create the table with proper types

                Use SERIAL for auto-incrementing id, VARCHAR(50) for name, NUMERIC(4,2) for age, and TEXT for description.

                Step 4: Why this is correct

                SERIAL automatically creates a sequence and sets the default value. NUMERIC(4,2) allows numbers like 99.99. VARCHAR limits length, while TEXT has no limit. These types match the requirements exactly.

                Final Answer: 
                -- Create the database
CREATE DATABASE sample_db;

-- Connect to it (in psql)
\c sample_db

-- Create the table
CREATE TABLE sample_table (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50),
    age NUMERIC(4, 2),
    description TEXT
);

                                Level 3.10 – Query Arrays: Contains 1 AND 5

                                Midterm – Section 3, Question 10

                                📋 Question:

                                Write a query that selects all data whose "interests" column contains the values 1 and 5 (in any order).

                                ✍️ Try it yourself:

                                  Step 1: Learn the @> operator

                                  The @> operator checks if an array contains all elements of another array.

                                  Step 2: Create the search array

                                  We want to find arrays that contain both 1 AND 5, so we search for '{1,5}'.

                                  Step 3: Write the WHERE clause

                                  Use WHERE interests @> '{1,5}' to find rows containing both values.

                                  Step 4: Why this is correct

                                  The @> "contains" operator returns true only if the left array contains all elements from the right array. So interests @> '{1,5}' will match '{1,3,5}' and '{1,2,3,4,5}' but not '{2,4}'.

                                  Final Answer: 
                                  SELECT *
FROM sample_table
WHERE interests @> '{1,5}';

                                  Level 3.11 – Query Arrays: Contains 2 NOT 4

                                  Midterm – Section 3, Question 11

                                  📋 Question:

                                  Write a query that selects all data whose "interests" column contains the value 2 but not the value 4.

                                  ✍️ Try it yourself:

                                    Step 1: Check for 2 using @>

                                    Use interests @> '{2}' to find arrays containing 2.

                                    Step 2: Exclude 4 using NOT

                                    Use NOT interests @> '{4}' to exclude arrays containing 4.

                                    Step 3: Combine with AND

                                    Use both conditions in the WHERE clause with AND.

                                    Step 4: Why this is correct

                                    This finds rows where 2 is present AND 4 is absent. Looking at our data: John has {1,3,5} (no 2), Jane has {2,4} (has 2 but also has 4), Bob has {1,2,3,4,5} (has both). None match! But the query structure is correct for this type of filtering.

                                    Final Answer: 
                                    SELECT *
FROM sample_table
WHERE interests @> '{2}'
  AND NOT interests @> '{4}';

                                    Level 3.12 – Append to Array

                                    Midterm – Section 3, Question 12

                                    📋 Question:

                                    Write a query that updates the "interests" column of the row with id=1 to add the value 2 at the end of the array.

                                    ✍️ Try it yourself:

                                      Step 1: Use array_append function

                                      PostgreSQL provides array_append(array, element) to add an element to the end of an array.

                                      Step 2: Reference the existing array

                                      Use the column name itself: array_append(interests, 2) appends 2 to the current interests array.

                                      Step 3: Write the UPDATE with WHERE

                                      Update where id=1 to target the specific row.

                                      Step 4: Why this is correct

                                      array_append preserves the existing array values and adds the new value at the end. So if interests was '{1,3,5}', it becomes '{1,3,5,2}'. This is better than manually reconstructing the array.

                                      Final Answer: 
                                      UPDATE sample_table
SET interests = array_append(interests, 2)
WHERE id = 1;

                                      Level 4.1 – Backup Database to SQL File

                                      Midterm – Section 4, Question 1

                                      📋 Question:

                                      Assuming you want to perform a backup using pg_dump, write the command to backup the entire database to a plain SQL file named "mydb_backup.sql". Make sure to include any necessary options and parameters.

                                      ✍️ Try it yourself:

                                        Step 1: Identify the tool

                                        pg_dump is PostgreSQL's utility for backing up databases.

                                        Step 2: Specify the database name

                                        Use -d database_name or just database_name as the last argument.

                                        Step 3: Specify output file

                                        Use -f mydb_backup.sql or redirect output with > mydb_backup.sql.

                                        Step 4: Complete command

                                        By default, pg_dump creates plain SQL format, which is what we want.

                                        Step 5: Why this is correct

                                        This creates a plain-text SQL file containing all the commands needed to recreate the database. The -f flag specifies the output file. This format is human-readable and can be restored with psql.

                                        Final Answer: 
                                        pg_dump -d mydb -f mydb_backup.sql

-- Alternative syntax:
pg_dump mydb > mydb_backup.sql

                                        Level 4.2 – Restore from SQL File

                                        Midterm – Section 4, Question 2

                                        📋 Question:

                                        Write the command to restore the entire database from the plain SQL file "mydb_backup.sql". Make sure to include any necessary options and parameters.

                                        ✍️ Try it yourself:

                                          Step 1: Identify the tool

                                          psql is used to restore from plain SQL files (created by pg_dump).

                                          Step 2: Specify the database

                                          Use -d database_name to specify which database to restore into.

                                          Step 3: Specify the input file

                                          Use -f mydb_backup.sql to read from the backup file.

                                          Step 4: Why this is correct

                                          psql executes all SQL commands in the file. The -d flag specifies the target database, and -f specifies the file to read. You may need to create the database first if it doesn't exist.

                                          Final Answer: 
                                          psql -d mydb -f mydb_backup.sql

-- Alternative syntax:
psql mydb < mydb_backup.sql

                                          Level 4.3 – Restore from Directory Format

                                          Midterm – Section 4, Question 3

                                          📋 Question:

                                          Write the command to restore the entire database from the directory "mydb_backup_dir". Make sure to include any necessary options and parameters.

                                          ✍️ Try it yourself:

                                            Step 1: Identify the tool

                                            pg_restore is used for directory-format and custom-format backups (not plain SQL).

                                            Step 2: Specify the database

                                            Use -d database_name to specify the target database.

                                            Step 3: Specify the backup directory

                                            Provide the directory path as the last argument.

                                            Step 4: Why this is correct

                                            pg_restore handles non-plain-text backup formats. The -d flag connects to the database and restores the data. Directory format allows parallel restore and selective table restoration, making it more flexible than plain SQL.
